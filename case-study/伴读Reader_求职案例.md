# 伴读 Reader

## 为长文、学习材料和严肃内容设计的低阻力阅读辅助

**Product case study | 独立项目**  
产品定义 · UX / interaction · 前端实现 · 双语本地化 · 迭代验证

在线版: https://sheahe-alex.github.io/slowglow-reader/  
代码: https://github.com/sheahe-Alex/slowglow-reader

## 01. 问题：不是不想读，而是很难进入

面对论文、课程材料、长邮件或专业文档时，阻力往往发生在真正理解之前：整屏文字带来过载，注意力容易漂移，朗读和高亮不一定同步，读到一半后很难返回重点。长期的失败体验还会叠加羞耻和自我否定。

我希望做的不是一个替用户总结的工具，而是一个让人可以一次次回到原文的阅读脚手架。

> **让阅读更容易开始，也更容易继续。**  
> Make reading easier to start, and easier to keep going.

### 设计约束

- 本地优先: 不登录、不上传文字、不接入在线 AI
- 不抢走学习过程: 不用自动总结替代用户理解
- 低启动成本: 打开网页、粘贴文字、马上开始
- 适配真实场景: 网页、PDF、文档、课程材料、长邮件
- Every feature must earn its weight.

## 02. 产品逻辑：进入、看见、留下、返回

我把阅读过程拆成四个连续动作，而不是把功能堆在同一层界面里:

1. **进入 Enter**: 大字号、保留段落、粘贴或读取剪贴板、示例文本
2. **看见 Notice**: 当前词高亮、可选朗读、结构提示、专注阅读
3. **留下 Leave traces**: 标记句子、少量回看词和回看句、自己的笔记提示
4. **返回 Return**: 点击回看线索跳回原文，暂停后前后句移动，支持多次阅读

这些机制共同服务一个目标: 让用户保留自己的理解，而不是获得一个看似完成的结果。

## 03. 关键设计决策

### 让注意力有落点，但不制造新的噪音

- 普通模式只突出当前词，结构提示使用下划线、点线和少量色块表达关系
- 专注阅读才突出整句，周围内容退后，当前词继续移动
- 结构提示默认自动适配中英文，中文侧重逻辑信号和概念复现，英文侧重信息流
- 英文词首加粗默认开启，但仅作为低强度视觉引导，设置里可关闭

### 让控制权跟着阅读动作走

- 暂停和继续是同一个动作，避免两个按钮表达同一件事
- 暂停后可以上一句 / 下一句，不必从头播放
- 速度在阅读中也可以调整，并在继续时生效
- “标记这一句”被放到专注阅读的当前句旁，而不是全局工具栏
- 停止后收起输入区和设置，让页面回到自由浏览状态

### 把回看做成脚手架，不做自动答案

回看线索使用本地规则，仅提供少量候选: 高频词、特殊名词、可能的关键句和用户手动标记。候选可以点击回到原文，也明确标注“不是 AI 总结”。

## 04. 迭代：从真实阻力反推产品

这个项目不是一次性完成的页面，而是通过持续使用和反馈逐步收敛。每一轮都问同一个问题: 它是在帮助用户回到阅读，还是把用户带离阅读?

| 观察到的阻力 | 设计回应 |
| --- | --- |
| 一整段高亮让人不知道当前读到哪里 | 改为逐词高亮，并加入朗读与视觉推进同步 |
| 长文本朗读中途漏读、读完一小段就结束 | 按句子和短块切分语音，继续时从当前位置接着走 |
| 语速、暂停、继续的语义不清 | 统一暂停 / 继续，支持阅读中调整速度并保留偏好 |
| 专注阅读里整句绿色背景随每个词闪动 | 取消整句动画，只保留当前词的轻微出现效果 |
| 结构提示和当前句整块背景叠加，视觉过载 | 普通模式取消整句背景，结构提示只表达关系 |
| 新用户可能永远发现不了专注阅读 | 第一次放入较长文本时轻量询问是否体验 |
| 顶部按钮越来越多 | 将主要动作、阅读控制和低频设置分层，并持续做减法 |

## 05. 结果与边界

### 已交付

- 可在 Windows、Mac 和移动浏览器使用的响应式网页原型
- GitHub Pages 在线版，无需安装、注册或登录
- 中文 / English 界面，浏览器语言自动识别，也保留手动切换
- 浏览器系统语音、当前词高亮、专注阅读、结构提示和本地回看线索
- 保留原文段落与换行，支持从第一遍阅读到第 N 遍回看

### 我学到的

辅助阅读产品的“温柔”不主要来自鼓励文案，而来自结构: 更少的选择、更清楚的当前状态、更容易回到上一步，以及不把用户的困难解释成能力不足。

### 诚实的边界

当前仍是启发式原型: 系统语音质量因设备而异，朗读和高亮仍可能有轻微时差，结构提示不是语义真理，PDF/OCR 尚未进入核心流程，也还没有正式的长期用户研究。

下一步应该先做小规模可用性测试，观察不同阅读者能否更顺利开始、回来和坚持，而不是继续增加功能。

> **The product is not a finished answer. It is a gentler doorway back to the text.**
